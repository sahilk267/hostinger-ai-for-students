# Phase 5 — SEO Discovery to Learning Conversion
**Date:** 2026-11-12
**Scope:** GitHub source updates only; no deployment, Search Console access, live analytics or automated tests claimed.

## Implemented
1. **Three editorial learning clusters** in `client/src/data/learningClusters.ts` and public route `/resources/:slug`:
   - `/resources/ai-study-skills`
   - `/resources/ai-safety-and-fact-checking`
   - `/resources/visual-ai-and-robotics`
   Each includes an audience, practical introduction, authored common questions and answers, relevant guide links, and concrete practice actions. Content is a focused hub, not fabricated expert certification or 120 automatically generated thin pages.
2. **Indexable initial HTML:** Express production handler serves cluster heading, explanatory text, guide/practice links and questions in the initial HTML response. Route-specific title, description and canonical metadata are generated by the existing SEO rendering helper. Unknown cluster and guide slugs respond with HTTP 404 and noindex rather than the SPA 200 fallback.
3. **120-topic mapping improvement:** `client/src/lib/topicResources.ts` maps each of eight curriculum tracks to a relevant guide and a distinct practical exercise. Two study topics and two prompt topics receive more specific mapping. UI explicitly discloses when a resource is only related background rather than a dedicated lesson.
4. **Discovery links:** The homepage now features three clusters; the guide library links to them; each guide links to matching clusters and each cluster links to related clusters and an appropriate practice activity. The sitemap includes all three public cluster URLs.
5. **Privacy-aware conversions:** `client/src/pages/LearningClusterPage.tsx` tracks `resource_guide_click` and `resource_practice_click` through the existing optional Umami wrapper. Guide articles track `guide_practice_click`. Events contain only public content slug and route path, never child identity, user-provided answers or profile data. Events are no-ops unless analytics is configured.

## SEO caveats / dependencies
- Canonical host is still hard-coded as `https://aiforstudents.in`; confirm the real production domain and enforce one primary host before deployment.
- These server HTML responses work only when production requests reach the Node/Express app. Static-only hosting of the Vite bundle will not provide the server-rendered content.
- Production Search Console indexing, impressions, ranking, traffic and conversion are not verified; no traffic impact is promised.
- Search engine page quality depends on original helpful content and actual usage, not merely meta tags or sitemap submission.
- Full SSR/static prerendering for all public routes remains architectural work.
- Error routes remain SPA fallbacks outside the specifically handled guide/resource slugs.
- Build, TypeScript and browser tests were not executed in this feature-focused delivery.
